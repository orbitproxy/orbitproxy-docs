连接你任何形态（Streamable HTTP, Stdio），任何位置（远程， 内网， localhost本地）的MCP 服务，并为其提供统一的认证鉴权， 访问控制，以及强大的可观测性

直接连接到 MCP 服务时，每个AI Agent都需要为每台服务器单独配置凭据。而使用 MCP 网关，客户端只需向 orbitproxy 进行一次身份验证。网关会处理所有已配置MCP 服务的凭据注入、权限检查和请求日志记录。

当 AI 代理/MCP 客户端调用 MCP 工具时，请求会经过 orbitproxy。网关使用代理的 API 密钥（或 IdP 令牌）验证请求，检查该用户是否拥有对所请求服务器和工具的访问权限，然后注入上游服务器的相应凭据——例如，github, 企业微信等服务的 OAuth 令牌、公共服务器的 API 密钥或内部服务器的身份标头。请求被代理到 MCP 服务器，完整的请求/响应过程会被记录。
这使得平台团队能够完全了解 MCP 的使用情况——谁在何时以何种参数访问了什么——而开发人员无需管理凭据或为每个服务器请求权限即可访问工具。
