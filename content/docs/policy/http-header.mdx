<PolicyTag scope="api" />

添加/移除 HTTP Header 策略在请求转发到上游服务之前，或响应返回给调用方之前，添加或移除指定的 HTTP Header。该策略不会拦截请求，流量仍按云端点配置转发。

一条规则只执行一种操作，由作用方向决定：追加请求头、移除请求头、追加响应头，或移除响应头。

## 配置参考

### 执行阶段

追加或移除请求头时，在请求到达网关之后、转发到上游服务之前执行。追加或移除响应头时，在上游服务返回响应之后、响应返回给调用方之前执行。

### 配置字段

<DocsTable>

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 规则的名称，用于区分同一云端点上的多条规则 |
| 作用范围 | 「整个 Proxy」或「指定路径」。选择指定路径时，再选择前缀匹配或精确路径匹配 |
| 作用方向 | 「追加请求头」「移除请求头」「追加响应头」「移除响应头」 |
| Header | 字段名称。追加时需同时填写字段值；移除时只填写需要移除的字段名称 |

</DocsTable>

## 行为

- 追加请求头：将指定字段添加到进入网关的请求上，再转发到上游服务。
- 移除请求头：从进入网关的请求上移除指定字段，上游服务收不到该请求头。
- 追加响应头：将指定字段添加到上游服务返回的响应上，再返回给调用方。
- 移除响应头：从上游服务返回的响应上移除指定字段，调用方收不到该响应头。

作用范围为「整个 Proxy」时，该云端点上的所有请求都适用。作用范围为「指定路径」时，只对命中前缀或精确路径的请求适用。

## 示例

### 追加请求头

作用方向为追加请求头，作用范围为整个 Proxy，Header 名称为 `x-request-id`，值为 `edge`。上游服务收到的请求中带有 `x-request-id: edge`。

### 移除请求头

作用方向为移除请求头，Header 名称为 `x-trace-id`。即使调用方携带了该请求头，转发到上游服务时也会被移除。

### 追加响应头

作用方向为追加响应头，Header 名称为 `access-control-allow-origin`，值为 `*`。调用方收到的响应中带有该 CORS 响应头，上游服务无需修改代码。
