在云端点上要求 HTTP Basic Auth。用户名和密码正确的请求会转到上游，其余请求直接返回 `401 Unauthorized`，不会打到内网。

## 配置参考

这条策略在请求到达网关时执行。

## 行为

网关按 [RFC 7235](https://datatracker.ietf.org/doc/html/rfc7235) 校验 HTTP Basic Authentication。请求里的账号和已配置的 `username:password` 对得上，就继续往后转发，最后到达上游；对不上，请求在网关结束，返回 `401 Unauthorized`。

### 其他限制

密码最短 8 个字符，最长 128 个字符。`username:password` 里如果出现多个冒号，第一个冒号是用户名和密码的分界，后面的内容都算进密码。

### 校验过程

- 请求必须带 `Authorization` 头，形式是 `Authorization: Basic <credentials>`。`<credentials>` 是 `用户名:密码` 的 Base64。
- 校验通过后，请求继续转发到上游。
- 校验失败返回 `401`。浏览器会弹出原生用户名和密码框，让调用方重新提交。

## 在控制台怎么配

1. 打开对应云端点，切到 **流量策略**
2. 展开 **BasicAuth 基础鉴权**，点 **添加规则**
3. 填 **规则名称**
4. 在 **Credentials** 里按 `username:password` 添加账号，一行一组
5. 保存

## 示例

先把 `username:password` 做 Base64。`user:password1` 编码后是 `dXNlcjpwYXNzd29yZDE=`。

```bash
curl https://你的云端点/ \
  -H "Authorization: Basic dXNlcjpwYXNzd29yZDE="
```

凭证正确时，网关把请求转到上游，并返回上游的响应。

不带 `Authorization` 头，或用户名密码不对时，会收到 `401 Unauthorized`，浏览器会弹出登录框。
