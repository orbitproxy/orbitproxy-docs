title: IP访问控制
description: 按来源 IP 或网段放行或拒绝进入云端点的请求。
---

<PolicyTag scope="common" />

IP 访问控制策略按请求的来源 IP 放行或拒绝访问。一条规则只能选择一种模式：白名单或黑名单。名单中可以填写单个 IP 地址，也可以填写 CIDR 网段。未通过的请求在网关被拒绝，不会到达上游服务。

## 配置参考

### 适用范围

API 网关的 HTTPS 云端点和 TCP 云端点，以及 MCP 网关。

### 执行阶段

请求到达网关时执行。

### 配置字段

<DocsTable>

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 规则的名称，用于区分同一云端点上的多条规则 |
| 策略模式 | 「允许名单（白名单）」或「拒绝名单（黑名单）」。一条规则不能同时配置两份名单 |
| IP / CIDR 列表 | 要匹配的来源地址。单个 IP 写作 `203.0.113.10`，网段写作 `203.0.113.0/24` |

</DocsTable>

## 行为

网关使用请求的来源 IP 与名单进行匹配。

- 白名单：来源地址至少命中名单中的一项才会放行，其余请求在网关被拒绝。
- 黑名单：来源地址命中名单中的任意一项即被拒绝，未命中的请求照常转发。

拒绝发生在网关，上游服务不会收到这次请求。

### 其他限制

名单至少需要包含一项。名单中的每一项必须是合法的 IP 地址或 CIDR 网段，否则规则无法保存。

## 示例

### 白名单

名单为 `203.0.113.10/32`，策略模式为白名单。来源为 `203.0.113.10` 的请求转发到上游服务，其他来源的请求在网关被拒绝。

### 黑名单

名单为 `198.51.100.0/24`，策略模式为黑名单。来源属于该网段的请求在网关被拒绝，网段以外的请求照常转发。
