title: API 访问密钥

<PolicyTag scope="common" />

API 访问密钥策略要求请求在指定的请求头中携带合法的密钥。携带合法密钥的请求转发到上游服务；未携带或携带错误密钥的请求在网关被拦截，不会到达上游服务。密钥可以随时撤销。

## 配置参考

### 适用范围

API 网关的 HTTPS 云端点，以及 MCP 网关。

### 执行阶段

请求到达网关时执行。

### 配置字段

<DocsTable>

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 规则的名称，用于区分同一云端点上的多条规则 |
| 作用范围 | 「整个 Proxy」或「指定路径」。选择指定路径时，再选择前缀匹配或精确路径匹配 |
| 请求头 | 调用方携带密钥所使用的请求头名称，默认为 `x-api-key` |
| 凭证 | 名称和密钥。名称用于区分多条凭证，密钥是请求头中需要携带的值 |

</DocsTable>

## 行为

网关读取已配置的请求头，并将其值与凭证中的密钥逐一比对。

- 请求头的值与任意一条密钥一致时，请求继续转发到上游服务。
- 请求未携带该请求头，或其值与所有密钥都不一致时，请求在网关终止。

作用范围为「整个 Proxy」时，该云端点上的所有请求都需要携带密钥。作用范围为「指定路径」时，只校验命中前缀或精确路径的请求。

### 撤销密钥

从凭证中删除某一条密钥后，携带该密钥的请求会被网关拦截。

## 示例

请求头使用默认的 `x-api-key`，凭证中的密钥为 `<API_KEY>`。

```bash
curl https://<云端点域名>/v1/orders \
  -H "x-api-key: <API_KEY>"
```

密钥正确时，网关将请求转发到上游服务，并返回上游服务的响应。请求未携带 `x-api-key`，或其值不正确时，请求在网关被拦截。
