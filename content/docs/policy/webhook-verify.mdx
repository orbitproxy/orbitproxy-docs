title: Webhook 验证
description: 校验 webhook 回调签名后再转到内网。
---

这条规则只出现在 API 网关的 HTTPS 云端点上。请求到达网关时，按已选的 webhook 身份源校验来源；通过后才转发到上游，没过的请求不会打到内网。

凭证不写在规则上。微信支付和支付宝的平台证书、互亿无线的路径口令，都放在事先建好的身份源里，规则只引用那一条身份源。

## 行为

网关用身份源里的材料核对这次回调是不是那个平台发出的、内容有没有被改过。核对通过，请求继续转到上游；核对失败，请求在网关结束，不会进入内网。

### 校验过程

- 微信支付、支付宝：用身份源里的平台证书验签，确认回调来自对应平台，并且报文体没有被篡改。
- 互亿无线：平台没有签名。身份源里配置路径口令 `pathToken`，回调路径必须以 <code>/{"{pathToken}"}</code> 结尾，网关按这个口令确认接收地址。
- 校验通过后，请求转发到上游。互亿无线要求源站处理完回纯文本 `success`。

## 在控制台怎么配

1. 先在控制台建好 **webhook 身份源**（微信支付、支付宝或互亿无线）
2. 打开对应 HTTPS 云端点，切到 **流量策略**
3. 展开 **Webhook 验证**，点 **添加规则**
4. 填 **规则名称**
5. **回调路径** 填精确路径，必须以 `/` 开头，且不能只是 `/`，并与平台配置的回调 URL 路径一致。互亿路径还必须以 <code>/{"{pathToken}"}</code> 结尾
6. **webhook 身份源** 选刚建好的那条
7. 保存

互亿无线：把 `https://<云端点域名><回调路径>` 填进互亿控制台的数据接收地址。

验签和回调重放的背景见 [Webhook 网关](/docs/gateway/webhook)。
