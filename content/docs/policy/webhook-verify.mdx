<PolicyTag scope="api" />

Webhook 验证策略在回调请求到达网关时，按所选的 webhook 身份源校验请求来源。校验通过的请求转发到上游服务，未通过的请求在网关终止，不会到达上游服务。

策略规则本身不保存凭证。微信支付和支付宝的平台证书、互亿无线的路径口令，都保存在预先创建的 webhook 身份源中，规则只引用其中一个身份源。

## 配置参考

### 适用范围

仅适用于 API 网关的 HTTPS 云端点。

### 执行阶段

请求到达网关时执行。

### 配置字段

<DocsTable>

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 规则的名称，用于区分同一云端点上的多条规则 |
| 回调路径 | 精确匹配的路径。必须以 `/` 开头，不能仅为 `/`，并且需要与第三方平台中配置的回调 URL 路径一致。互亿无线的回调路径还必须以 `/<pathToken>` 结尾 |
| webhook 身份源 | 已创建的 webhook 身份源，规则使用其中的材料完成校验 |
| 回调类型 | 仅微信支付需要选择，可选「支付回调」「退款回调」「签约 / 解约」。支付、退款、签约必须各使用一条路径，Edge 验签后只放行对应的 `event_type` |

</DocsTable>

## 行为

网关使用 webhook 身份源中的材料，核对回调是否由对应平台发出，以及内容是否被篡改。核对通过后，请求继续转发到上游服务；核对失败时，请求在网关终止，不会进入内网。

### 校验过程

- 微信支付、支付宝：使用身份源中的平台证书验签，确认回调来自对应平台，且报文体没有被篡改。
- 互亿无线：平台不提供签名。身份源中配置路径口令 `pathToken`，回调路径必须以 `/<pathToken>` 结尾，网关据此确认接收地址。
- 校验通过后，请求转发到上游服务。互亿无线要求上游服务处理完成后返回纯文本 `success`。

## 支持的身份源

<DocsTable>

| 身份源 | 校验方式 |
| --- | --- |
| 微信支付 | 平台证书验签 |
| 支付宝 | 平台证书验签 |
| 互亿无线 | 无签名，使用路径口令 `pathToken`，回调路径以 `/<pathToken>` 结尾 |

</DocsTable>

## 示例

### 微信支付

回调路径为 `/api/webhook/wxpay/payment`，webhook 身份源选择已创建的微信支付身份源，回调类型选择「支付回调」。

微信支付向 `https://<云端点域名>/api/webhook/wxpay/payment` 发送的回调，经平台证书验签通过后转发到上游服务。验签失败的请求在网关终止。

### 互亿无线

身份源中的路径口令为 `<pathToken>`，回调路径为 `/api/webhook/ihuyi/<pathToken>`。在互亿无线的数据接收地址中填写 `https://<云端点域名>/api/webhook/ihuyi/<pathToken>`。路径不以该口令结尾的请求在网关终止。

验签和回调重放的背景，见 [Webhook 网关](/docs/gateway/webhook)。
